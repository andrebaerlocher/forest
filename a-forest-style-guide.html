Concept

The interface is a tea box.

Two materials, one seam. Paper carries the work; ink carries the tools. They never meet in a straight line — the boundary is the wave. Light mode is the closed lid; dark mode is the opened box, tone-on-tone. One thing never changes: the linen tan, the fixed point of the system. Every rule below is derivable from this paragraph. If a component decision isn't, the decision is wrong or the paragraph is.

Foundations

Color & themes — OKLCH

All ink colors live in OKLCH as an ink ladder: five lightness steps at one chroma band (0.045–0.055) and one hue. Theming an app means rotating --hue — try the slider in the spine. Paper, the tan accent, and the status hues never rotate; they are the materials that stay on the table while the ink changes.

Theme recipe & caveats 
:root { --hue: 282; }        /* indigo — flagship   */
/* per app:  165 pine · 20 oxblood · 250 slate      */

--ink-3: oklch(29% 0.055 var(--hue));
--wash:  oklch(29% 0.055 var(--hue) / 5%);

Caveats, honestly: (1) chroma 0.055 at L 19–38% is inside sRGB gamut for all hues, but if you raise chroma, yellows/cyans clip first — keep the band. (2) OKLCH lightness is perceptual, WCAG contrast is not; equal L does not guarantee equal contrast ratios, so every theme still runs the AA checks as acceptance tests. (3) Hues 60–100 collide with the tan accent — a theme there loses the invariant's uniqueness; skip that arc. (4) A theme is exactly one number plus passing tests. If it needs more overrides than that, it's a fork, not a theme.

Foundations

Ink surfaces — .on-ink

The tokens above describe paper. A component dropped on the spine, a drawer or the palette is standing on ink, and every one of those tokens is now backwards: --text-1 is near-black, --line-soft is a near-white paper hairline, --wash is dark ink at 5%. Left alone, a list row on the spine paints its title in exactly the colour of the surface behind it.

So ink surfaces carry a scope that flips the canvas tokens locally. Anything rendered inside reads correctly with no per-component override:

.on-ink {
  --text-1: oklch(94.5% 0.012 95);
  --text-2: oklch(94.5% 0.012 95 / 72%);
  --text-3: oklch(94.5% 0.012 95 / 45%);
  --line-soft: oklch(94.5% 0.012 95 / 10%);
  --line-mid:  oklch(94.5% 0.012 95 / 18%);
  --wash:      oklch(94.5% 0.012 95 / 10%);
  --wash-hover:oklch(94.5% 0.012 95 / 5%);
  /* status lightens to survive on ink — the dark-mode values */
}

Status colors

Ledger logic: status is ink, not paint. Red ink for negative numbers is two centuries of bookkeeping — status colors appear as text, icons, thin rules, and dots, never as large fills or tinted panels. Fixed hues; only lightness flips between modes.

Signature

The wave edge

One wave per persistent surface. Transient surfaces — palette, drawer, toast — may carry it, because they are pieces of the box moving. Amplitude: 26 px documents, 12 px spreadsheets. Irregular control points; a perfect sine reads as decoration.

Editing
Recipe 
td       { padding: 0; }            /* the cell contributes no inset      */
.cellbox { display: block;          /* …the box does, so rings fill the cell */
           padding: calc(var(--pad-cell-y) + 2px) 15px;
           border: 1.5px solid transparent; border-radius: 3px; }
.cellbox.selected { background: var(--cell-sel-bg);
                    border-color: var(--cell-sel-border); }
.cellbox.editing  { background: var(--cell-sel-bg);
                    border-color: var(--cell-sel-border);
                    box-shadow: inset 0 0 0 1px var(--cell-sel-border); }

The calc() matters: it re-absorbs the inset the <td> used to contribute, so moving the padding onto the box changes no row height and no column width. [data-density] still remaps, because --pad-cell-y is inherited and just as reachable on the box.

Selecting and editing wear the same skin. Selection is the state you read a cell in; editing is the same cell with a caret, so it earns emphasis (a 1 px inset ring), not a different material. Two consequences worth having: a negative number stays in danger ink while you edit it, and the tan ring is the one selection idiom across cells, calendar days and list rows. Click selects; double-click, Enter, F2 or simply typing opens the editor. Editing is in-cell; the formula bar mirrors, it doesn't own.

The older rule — light mode edits in ink, dark mode edits in tan — is retired. --cell-edit-bg and --cell-edit-text survive as the system's inversion pair: they still drive the primary button, the checked box, the switch and the active segment.

Component recipes

Atoms

Each atom below is rendered live and ships with its styling recipe. Shared laws: transparent-border box model (state changes never move pixels); focus is always outline: 1.5px solid var(--accent); outline-offset: 2px; color/border transitions at --t-fast, position never transitions.

Slips — the card, disciplined

Where you'd reach for a card grid, first try ledger rows or hairline-delimited regions. When a bounded object is truly needed — KPI tiles, kanban items, menus, confirm dialogs — use a slip: the paper band from the packaging. Flat, bordered, radius-m, no shadow at rest. Shadow exists in one state only: while dragged. That single constraint keeps slips from decaying into Material cards.

Modes

Density

A second attribute next to mode: data-density="comfortable | compact". It remaps three tokens — --pad-cell-y, --pad-control-y, --font-data — and every table, input, and button follows. Spreadsheets and inventory default compact; forms and editors comfortable. Try it:

The ledger table and all inputs above respond. Density never changes type scale — headings and body stay put; only data rows and controls tighten.

Modes

Elevation

Stacking is a token scale; shadow is an event. Order: sticky headers (10) < drawer (40) < palette (50) < toast (60) < tooltip (70). Overlay scrims are the ink at low alpha — oklch(19% .05 var(--hue) / 40%) — the room dimming, not going grey. Shadows appear in exactly two situations: a dragged slip, and transient surfaces while entering (palette, drawer), where --shadow-drag doubles as their separation from the page.

Modes

Motion

Paper doesn't animate; it moves. Three durations, one curve: --t-fast 120ms for color/border micro-feedback, --t-base 200ms for the switch thumb and small reveals, --t-slow 320ms for mode/theme changes and transient surfaces. Easing is always --ease (ease-out).

Svelte rule: transition: directives are reserved for transient surfaces — fly for palette and drawers (pieces of the box entering), fade for toasts and scrims. Persistent layout changes instantly. Nothing transitions top/left/width; position only ever moves via transform, and only on the transient list plus the switch. prefers-reduced-motion zeroes everything.

Modes

Scrollbars

Default scrollbars are foreign chrome on paper. Two sanctioned treatments: styled-minimal (default) — thin thumb in --scroll-thumb (ink at 20% / paper at 18%), transparent track; and hidden — allowed only where the component carries its own position indicator (the spine nav, carousels, the table with its row counter). Never hidden on long-form reading surfaces.

Discipline

Rules

Do
Theme by rotating --hue only; a theme is one number plus passing contrast tests.
Don't
Rotate paper, accent, or status hues — the materials stay on the table.
Do
Use status as ink: text, dots, thin rules, negative numbers.
Don't
Paint status: no tinted panels, no filled red buttons, no large fills.
Do
Prefer ledger rows and hairline regions; use slips only for truly bounded objects.
Don't
Shadow anything at rest. Elevation is a z-token; shadow is drag or entry.
Do
Reserve Svelte transitions for transient surfaces; move position via transform only.
Don't
Animate persistent layout, scroll position, or anything at all under reduced-motion.
Do
Keep the tan accent to three appearances per view; focus ring is always tan.
Don't
Ship default scrollbars, mono text-strings, a second resting wave, or neutral greys on ink.
Do
Wrap anything standing on ink in .on-ink; let the tokens flip once, centrally.
Don't
Hand-patch a component's colours because it landed on the spine — that's the scope's job.
Do
Let the state ring fill the whole cell; selection and editing share one skin.
Don't
Put padding on both the cell and its box — the inset belongs to exactly one of them.
